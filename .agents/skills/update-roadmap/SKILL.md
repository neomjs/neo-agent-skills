# Update Roadmap
If you are running the post-release planning beat — celebrating a shipped release and scoping the next one (its milestone's cornerstones, rationale, deferred set, and epic stewards) — you MUST immediately use the `view_file` tool to read and strictly adhere to `.agents/skills/update-roadmap/references/update-roadmap-workflow.md` before drafting any roadmap, milestone, or scope artifact.
## What it enforces
Sibling to `#10321` (`release-cut: notes + publish`): celebrates the shipped release, then plans the next roadmap as cornerstones + rationale (NOT an exhaustive list) + an explicit deferred set, scoped into a GitHub milestone with a named steward per epic.
