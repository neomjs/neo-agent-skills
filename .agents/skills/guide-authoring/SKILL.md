# Guide Authoring Skill

If you are authoring, relocating, OR reviewing a `learn/**/*.md` document (excluding `learn/blog/*.md`, owned by `blog-post`), you MUST immediately use the `view_file` tool to read and strictly adhere to `.agents/skills/guide-authoring/references/guide-authoring-bar.md` before choosing a section, writing the first sentence, or posting a review verdict.

A `learn/` document is held to a 9/10 bar: pre-write container placement against the repo's local `learn/tree.json` (§0), grounded by *using* the system's tools + memory-mining (not inference), narrative + benefits-driven with lived voice, render-verified TD Mermaid diagrams, conceptual-vs-reference separation, never hand-editing generated files, and a no-rubber-stamp reviewer gate against the WHOLE bar. Skipping it is the higher-cost path — MemoryCore took ~7 cycles and KnowledgeBase a rubber-stamp reversal precisely because this discipline was skipped.
