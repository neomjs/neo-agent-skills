## §friction_to_gold
Friction → gold is the **core value** governing substrate evolution via the MX loop (Discussion #10137), converting §verify_before_assert-validated friction into substrate improvement. **With V-B-A, these 2 core values form the evolution flywheel**: V-B-A filters real friction from hallucinated; friction → gold converts validated friction to substrate.

**Tier hierarchy — core values > values > rules**: **Core values** (§verify_before_assert + §friction_to_gold) govern substrate evolution; **Values** (§self_evolving_systems, §neo_identity_anchor, §swarm_topology_anchor, skill disciplines) sit between; **Rules** (§critical_gates) derive mechanically from values. The MX loop operates across all three: rules evolve quickly on friction, values via multi-cycle peer dialogue, core values rarely (high-bar challenge). Place new substrate at the right tier — misplacing a rule as a core value or vice versa is an anti-pattern. Atlas detail: §anti_hallucination_policy.
